Spoiler Guard
blur_on
Spoiler Guard hides episode thumbnails, season posters, movie posters and chapter scenes for unwatched titles each user opts into. It also strips spoiler-bearing metadata: synopses, episode titles, tags, taglines, ratings, air dates, cast on unwatched episodes, chapter names, and TMDB / user reviews on opted-in series.
Turns the whole feature on. While it's off, the per-show toggle button never appears and nothing is ever hidden. Turn it on to let users protect individual shows, movies, and collections from their own detail pages.
How protected cards look. Show stock cards (default) swaps each unwatched image for a safe parent-level placeholder: episodes show their series backdrop, seasons show the series poster, collection-opted movies show the collection art. Blur images instead applies a strong blur to the original so silhouettes and dominant colours still hint at "something is here". Pick stock cards for the strictest hide; pick blur if the placeholders feel too aggressive.
How strong the blur is. 5 is barely smudged, 40 is the recommended default (characters become unrecognisable but the colours still come through), 100 is almost a solid colour wash. Applies to "Blur images" mode, and to "Show stock cards" mode when an item has no safe parent art to substitute (e.g. a directly-opted-in movie), where the original is blurred as a fallback.
By default the protection covers posters, episode thumbs, and screenshots, but leaves the wide cinematic backdrop / fanart on detail pages alone (it's usually atmosphere, not plot). Turn this on if you want backdrops hidden too for maximum protection.
When on, a protected movie's poster still shows in full, but the scene thumbnails inside the movie's detail page (chapters, screenshots) stay hidden. Useful if you find movie posters are usually marketing art that doesn't give plot away, while the chapter scene-thumbs inside the movie do. Doesn't affect TV shows.
When on, Spoiler Guard turns itself on for a series the moment a user starts Season 1 Episode 1 of a show they've never watched. They don't have to remember to flip the toggle before pressing play. Rewatches and jumping in at later episodes are ignored; only a fresh first-play counts.
When on, requesting something through Seerr also pre-arms Spoiler Guard for that title: when the show or movie lands in the library, protection is already on for the user who requested it. Users can also pre-arm titles manually with the "Enable Spoiler Guard" button in the Seerr details popup (always available regardless of this toggle), handy when someone else requested the title first.
When on, every new show or movie that appears in the library (from a scan, a Seerr download, or a manual copy) is added to the Spoiler Guard list of every user who can see that library, so protection is in place before anyone presses play. Only brand-new titles are affected: a user who later switches Spoiler Guard off for a title isn't re-armed by metadata refreshes. Library scans are batched, so a big scan results in one settings write per user rather than one per title.
Auto-enable applies to — shared by all three auto-enable options above.
Libraries — leave every library unticked to cover all of them. Doesn't apply to Seerr requests (the title isn't in a library yet).
Loading libraries…
Titles already in the library — auto-enable only arms titles as they arrive, and a rescan doesn't count (so nobody who switched Spoiler Guard off for a title gets it switched back on). To guard what's already there, apply the saved scope above to existing titles, for every user who can see them. Works whether or not "when new titles are added" is on. Titles a user already has, or has fully watched, are skipped. Also available as the "Spoiler Guard: apply to existing titles" scheduled task.
After a user flips Spoiler Guard on or off, card images update on the page instantly. By default, on-page text (description, episode titles, ratings) only refreshes when they navigate next. Turn this on to also reload the whole page after a toggle so the text updates straight away, at the cost of a brief page flash. Most users prefer it off for the smoother feel.

Displays the MDBList ratings row on item-details pages.
Enables the Fetch Ratings from MDBList scheduled task (Dashboard → Scheduled Tasks):
  • Looks up MDBList data for any movie/series whose cached ratings are missing or stale, and saves it. Doesn't touch Jellyfin's own rating fields
  • A found title stays cached for 7 days (3 days for a confirmed "no match") before being refetched. Already-fresh titles are skipped on a re-run, so it's safe to schedule this frequently, even daily
  • Stops once today's quota drops to the reserve below
The fetch task stops once today's live remaining quota drops to this many, reserving that much for people browsing the library (an item-details page fetches live if nothing's cached yet).
Enables the Sync Ratings from MDBList to Jellyfin scheduled task:
  • Sets Community (TMDB) / Critic (Rotten Tomatoes) Ratings from whatever's already cached (see Fetch above) into Jellyfin's own fields
  • Requires the Fetch Ratings from MDBList task to be enabled and run first
  • Off (default): Only fills an empty rating, never revisits an item once both are set
  • On: Every run re-sets every item's rating to MDBList's current cached value. This is also the only way ratings stay current over time

Automatic Requests
Auto Season Requests
Automatically request the next season in Seerr when a user about to finish the current season.

Require all episodes before the threshold to be watched. For example, if threshold is 2 and there are 10 episodes, when watching episode 8, all episodes 1-7 must be watched or marked as watched. This prevents accidentally triggering requests by jumping to later episodes.
This might cause requests to not be triggered if users skip episodes.
Request the next season when the number of unwatched episodes is at or below this number. Default: 2 episodes.
info
• Requests are triggered when users start or complete watching episodes
• Set threshold to 2-3 episodes to give time for downloading before users finish watching
• Example: With threshold set to 2, when user starts episode 8 of 10 of season 1, season 2 will be requested
• If a user has already triggered a request for the season, it will not be requested again even if another user reaches the threshold
Auto Movie Requests
Automatically request the next movie in a collection based on configured triggers.

Requirements: TMDB API key must be configured.
Request Triggers:
Trigger an auto-request for the next movie in the collection as soon as a user starts a movie.
Select one or both triggers. If both are selected, the request will be triggered if either condition is met.
How many minutes a user should watch before triggering a request? Must be between 1 and 180 minutes.
When enabled, future releases will be skipped. Only movies that have already been released will be requested.
Default: Seerr uses its default Radarr server and quality profile.
Original: Uses the same quality profile as the movie being watched (falls back to default if not found).
Custom: Always uses the specific Radarr server, quality profile, and root folder selected below.
Only applies when Quality Profile Mode is set to "Original". If the watched movie was requested with a 4K profile, the auto-request will use Seerr's default profile instead. This prevents requests from failing or requiring manual approval for users who don't have 4K request permissions in Seerr. Disable this if all your users have 4K request access and you want to preserve the original 4K profile.
These settings are only used when Quality Profile Mode is set to "Custom".
info
• Only works for movies that are part of a TMDB collection (e.g., The Avengers Collection, Star Wars Collection, etc.)
• Automatically requests the next movie in the collection based on release order
• Movies already available or requested will be skipped
Recently Added Sync to Seerr
When Jellyfin reports new library items added, enabling this triggers the "Jellyfin Recently Added Scan" job so that request statuses are immediately updated instead of waiting till next schedule run. Events are debounced, so a bulk import collapses into a single trigger.

Tip: With this enabled, you can set Seerr's recently-added scan Frequency to a much longer interval (60 minutes) to reduce noise.
Wait this many seconds after the LAST item added before firing the scan. Default 60. Range 5 to 3600.
Uses the Seerr URL and API key entered in the Setup section above. If multiple URLs are configured, the first reachable one is used.

When enabled, items will only be added to a user's watchlist once. If a user manually removes an item from their watchlist, it won't be automatically re-added during future sync runs.
How long to remember that an item was processed before allowing it to be re-added.
After this period, manually removed items (if unwatched) will be automatically re-added to watchlist if they're still in Seerr requests or Seerr watchlist.

Examples:
  • 30 days: Short memory, items can be re-added after 1 month
  • 365 days: Remember for 1 year (recommended)
  • 3650 days: Remember for 10 years (nearly permanent)
Note: This setting only applies when "Prevent re-adding removed items" is enabled.
Users
Automatically import Jellyfin users into Seerr so they can use Seerr Search without needing to visit Seerr directly. New users are imported the first time they use Seerr Search; a scheduled task also bulk-imports periodically. Already-imported users are skipped.

Configure the bulk import frequency in Jellyfin Dashboard > Scheduled Tasks > "Import Jellyfin Users to Seerr".
Blocked Users (none)
Select users to exclude from Seerr import. Blocked users will never be looked up or imported. No API calls are made for them.
