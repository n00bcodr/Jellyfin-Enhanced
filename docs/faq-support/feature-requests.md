# Feature Requests

Describe the problem you want to solve and how a change would help you use Jellyfin. You do not need to design the implementation.

## Before requesting

The feature may already exist behind a server switch or personal preference. A matching request may also have useful discussion you can build on.

1. Check the relevant [feature guides](../getting-started/index.md) and [Settings Overview](../getting-started/settings-overview.md).
2. Search [existing enhancement requests](https://github.com/n00bcodr/Jellyfin-Enhanced/issues?q=is%3Aissue+label%3Aenhancement).
3. If a matching request exists, add your use case and useful details there.

Use [GitHub Discussions](https://github.com/n00bcodr/Jellyfin-Enhanced/discussions) for an early idea or an open-ended conversation about possible approaches.

## Submit Feature Requests

Use the [feature request template](https://github.com/n00bcodr/Jellyfin-Enhanced/issues/new?template=feature_request.md) for a concrete proposal.

The template asks for:

1. **Is your feature request related to a problem? Please describe.** Explain the current workflow and where it falls short.
2. **Describe the solution you'd like.** Describe the behavior you want and how you would use it.
3. **Additional context.** Include relevant screenshots, mockups, or examples.

??? note "Details"

    If it does not open directly, use the [issue chooser](https://github.com/n00bcodr/Jellyfin-Enhanced/issues/new/choose) and select the feature request template.

## Good Feature Requests

A concrete example helps others understand the behavior you want: “When I open this page, I want to filter these results because…”.

Include:

- The client and layout you use.
- Whether the change is for administrators or viewers.
- Any service it depends on.
- The limitation of any existing setting or workaround you have tried.

Keep separate ideas in separate requests unless they form one workflow. Be open to a different solution that addresses the same problem.

!!! note

    A submitted request starts a discussion. It does not guarantee implementation or a release date.

If an existing feature is failing, use [Report issues](report-issues.md) instead.
