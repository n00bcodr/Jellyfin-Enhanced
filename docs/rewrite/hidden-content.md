# Hidden content and home-row removal

This slice replaces the 16 `js/enhanced/hiddencontent/*.js` entries and the two
`js/enhanced/homeremoval/*.js` entries with strict TypeScript. It does **not**
complete the JE rewrite or certify Jellyfin host parity.

## Source, boundaries and ownership

`client/entries/hidden-content.json` maps all 18 original resource paths to
`client/src/features/hidden-content/`. The existing component-script manifest and
loader order are unchanged. JavaScript and linked source maps are generated by
the shared client builder. The narrow adapter is
`client/src/features/hidden-content/host.ts`; no core, settings, bookmarks, Arr or
backend implementation was changed by this slice.

`model.ts` owns document, item, user-list, Jellyfin item and Seerr response
validation, identity normalization and scope merging. `page-model.ts` defines
management state and its contracts; `home-model.ts` defines the two removal
surfaces and error projection. The entry implementations receive the host through
an explicit adapter and exchange their feature interfaces through the existing
`JE.internals` registries. Unknown data is validated before entering typed state.
Document extension fields are intentionally represented as unknown data, not as
an unrestricted host API.

Only the data entry owns policy and lookup sets. Only the page-state entry owns
management state. A feature-local registry on the host owns installer identities,
the view generation, cleanup callbacks and the write queue. Imports bundled into
multiple entries therefore do not create competing stores or queues. Loading an
entry twice does not install another owner. Operations resolve the live API client when they start and bind transport, user,
server root, token and session epoch together. Loaded policy also retains its
owner, so replacing a client before bootstrap cannot save the previous policy
under the next identity. Session epochs cover user/server transitions; route and view-hide generations also invalidate confirmations and
asynchronous UI work. Administrator selection tokens are independent of session
changes. Old account page contents and overlays are cleared synchronously.

## Preserved behavior

- Global hiding remains separate from Continue Watching, Next Up and their union
  (`homesections`). GUID variants normalize for matching; TMDB-only identities
  remain supported. Existing collection settings and collection-card exclusions
  are retained.
- Native cards, parent-series cascading, HSS row detection, Seerr discovery and
  recommendations, request filtering and calendar filtering retain their public
  facades and default surface settings. Removal preserves playback progress.
- Hide confirmations, episode/show choices, suppression preferences, undo toast,
  searchable management panel, grouped series cards, expand/collapse, scope
  filters, own/admin pages, admin add/search/edit controls, native/custom tabs and
  Plugin Pages integration retain the existing resource paths and styles.
- The admin search retains its existing 24-result Jellyfin query and Seerr search
  behavior. The baseline management page renders its loaded document with client
  search/filtering; this slice does not add a new pagination protocol.
- Backend authorization and response filters are unchanged. Browser controls are
  presentation, never authorization.

## Intentional corrections

Malformed policy documents and admin lists are failures rather than authoritative
empty lists. Invalid bootstrap policy prevents writes until valid data is loaded.
Known PascalCase fields are decoded without recursively rewriting unknown fields
or storage keys. Scoped merges and ordinary edits preserve extension fields and
the earliest hide timestamp, comparing the full stored fractional precision across timezones and accepted legacy clock spellings. Known metadata falls back across aliases when the primary record has missing or empty fields; explicitly supplied edits still win. A missing legacy scope still means global.

The eight-second Undo toast survives same-account navigation and is disposed on identity change, expiry, replacement or page exit. Undo restores the preceding item records, including aliases, scopes and unknown
fields, when that operation is still applicable. Per-item edit generations let an
unchanged refresh retain Undo while rejecting later local or remote edits.
Ordinary and scoped hides widen existing home scopes and retain the original
spelling of the earliest hide timestamp across aliases. GUID unhide removes equivalent
storage aliases. Calendar name fallback no longer turns a home-only hide into a
global calendar hide. Disabling a scoped-only policy restores its cards. Empty
home rows are restored after undo, after the deferred card visibility pass.
Deferred visibility batches bind to the policy generation and recheck each
card identity and connectivity before applying changes.

Refreshes capture a policy revision and request sequence, so an edit followed by Undo or a settings revert cannot admit an older response. Only the newest outstanding refresh can publish its result. Whole-document saves and scoped writes are serialized per server-root/user document within this tab, retaining the bounded retry ladder. An unresolved write for another account or server cannot block the current document. Returning to the same document retains its outstanding write barrier to prevent completion reordering; a new session does not cancel an already-sent server write.
A sent scoped write remains a successful server mutation after navigation or an
account switch, but it cannot update a new account's UI. The data owner gives scoped writes a logical-item intent lease before the first wait, checking it again at queue release and acknowledgement. A newer local undo or explicit unhide on the same item survives the acknowledgement and is persisted by its queued corrective save, even when values revert. Reset and unhide-all invalidate all such leases; unrelated item/settings edits do not. Consecutive scoped hides still merge their scopes in server order. Parent responses cannot hide a recycled card for another item.
Admin completions cannot prune another selected user's list. Confirmations and
scheduled actions reject stale sessions, views and administrator selections.

## Validation and limits

Focused tests execute generated production JS in jsdom and Chromium; they do not
substitute TypeScript-only helpers for the shipped entry points. Evidence, exact
commands, source/output hashes and the handoff are under
`artifacts/rewrite-hidden-content/`. Existing assertions remain intact.

The legacy whole-document storage protocol remains a **multi-tab limitation**:
another tab or a server-side auto-clear can race a whole-document save. This
requires the backend document migration; the in-tab queue is not cross-client
concurrency control. A lost transport acknowledgement can also leave a scoped
write's outcome uncertain until a subsequent server refresh. No browser-only
change can make that endpoint transactionally revisioned.

Unknown-field preservation above applies at this client decoder boundary. The
legacy bootstrap camel-case conversion and typed backend documents still limit
end-to-end preservation, and unreadable-storage defaults can mask a malformed
policy before this decoder sees it. Revisioned hidden-content transport and
persistence remain required backend work.

The parent owns inventory regeneration, the combined gate, independent review,
backend authorization/filter checks and disposable Jellyfin 12.4.0 host runs.
This slice has not run real-host navigation, real Seerr/HSS integration, native
clients, mobile/Firefox, visual comparisons or a large-library performance test.
The prior 2,808 frontend / 2,792 backend / 55 host-check checkpoint is supplied
context, not validation of these new assets.
