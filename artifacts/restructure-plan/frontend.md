**Consequence: moving a source file does not change shipped file names or order**, provided the move edits only the right-hand side (source) of the `client/entries/*.json` mapping. It still causes churn:
1. the `// client/src/...` path comments inside affected `js/**/*.js` outputs,
2. `sources[]` in the matching `.js.map` files,
3. the `outputs` hashes and `entries[].source` in `client/generated-manifest.json`,
4. `docs/rewrite/migration-inventory.json` paths, and any test that imports a source by path (see §4).

All of this is mechanical and is regenerated by `npm run client:build`. Review outputs with `git diff --stat Jellyfin.Plugin.JellyfinEnhanced/js` and expect only comment and map-path changes. Rule for every step: **never rename an output key and never touch component-scripts.json** unless the step explicitly versions the output.

## 2. Cross-feature access design (finding c)

### 2.1 What exists today (verified)
- No feature reads `window` directly. Each `host/<x>-host.ts` reads `window.JellyfinEnhanced` and returns a typed bridge. Example: `host/tag-runtime-host.ts:151-155`, where `tagRuntimeHost()` does `host.JellyfinEnhanced ??= {}`, and `tag-pipeline-entry.ts` calls `createTagPipeline(tagRuntimeHost())`. Most of the ~4,000 `JE.` hits are therefore accesses on an **injected, typed parameter** named `JE`, not the raw global. Features import `host/` 199 times.
- Hits by area: settings-panel 1046, media-tags 554, seerr 430, details-providers 345, hidden-content 268, bookmarks 223, player 203, bootstrap 173, others under 165.
- Top members: `t` 1042, `currentSettings` 330, `core` 326, `session` 283, `pluginConfig` 283, `helpers` 182, `toast` 155, `internals` 86, `userConfig` 85, `hiddenContent` 65, `jellyseerrAPI` 50, `saveUserSettings` 49, `tagPipeline` 43, `state` 43, `jellyseerrUI` 40, `escapeHtml` 37.
- `JE.internals` appears in 13 feature folders. The owned slots I found are `enhancedUi` (settings-panel/registry.ts), `moreInfoModal` (host/seerr-details-host.ts:181,290), `recommendationsPage` (seerr-discovery-host.ts:90), `bookmarksLibrary`/`bookmarkLifetimes` (bookmarks-host.ts:8), `spoilerGuard` (seerr-details-host.ts:181, a cross-feature read) and `DetailsInternals` (details-providers-host.ts:164).
- Host bridges import feature types in the reverse direction, e.g. `host/tag-runtime-host.ts` imports 11 media-tags types. host/ is not a lower layer today.

### 2.2 Constraint that shapes the design
Each entry is bundled as its **own IIFE** (`client-build.mjs:178-205`). A runtime `import` of another feature's module **copies that code and its module state into the importing output**. Only these may be imported at runtime across features: pure, stateless functions, constants and data. Stateful services must come through the shared global, because scripts load separately in `component-scripts.json` order. That is why `import type` plus a registry is the rule.

### 2.3 Target: `FeatureContext<Own, Peers>`
New `client/src/host/context.ts`:
```ts
export interface CoreServices {            // injected; process-wide state on window.JellyfinEnhanced
  t: Translate; settings: SettingsReader /*currentSettings*/; saveUserSettings: SaveUserSettings;
  pluginConfig: PluginConfig; userConfig: UserConfig; session: Session; toast: Toast;
  core: { api: CoreApi; dom: Dom; ui: Ui; lifecycle: Lifecycle; navigation: Navigation };
  themer: Themer; cdn: Cdn; state: SharedState;
}
export interface FeatureContext<Own extends object, Peers extends object = {}> {
  core: CoreServices;
  own: Own;                                 // this feature's facade slot(s) + its own internals slot
  peer<K extends keyof Peers>(name: K): Peers[K] | undefined;   // lazy: peer may load later
}
export function featureContext<Own, Peers>(feature: FeatureName, ownKeys: readonly string[]): FeatureContext<Own, Peers>;
```
- `features/<f>/host.ts` (moved from `host/<f>-host.ts`) becomes `export const mediaTagsContext = () => featureContext<MediaTagsOwn, { hiddenContent: HiddenContentApi; seerr: SeerrApi }>('media-tags', ['tagPipeline','tagCacheStore', …])`.
- `features/<f>/public-api.ts` holds **types only**, plus the runtime key under which the facade is published. Peers import `import type { HiddenContentApi } from '../hidden-content/public-api'`.

| JE member(s) | Becomes | Why |
|---|---|---|
| `t`, `currentSettings`, `saveUserSettings`, `loadSettings`, `setSettingInherited`, `pluginConfig`, `userConfig`, `session`, `toast`, `state`, `themer`, `cdn`, `core.*` | **injected** `ctx.core.*` | process-wide mutable state, owned by bootstrap/core |
| `escapeHtml`, `icon`/`IconName`, `fontSizePresets`, `getSubtitleTextShadow`, `isVideoPage`, pure `helpers.*` | **direct import** from `core/` or `features/shared/` **[UNVERIFIED: purity must be checked per member before converting]** | stateless; duplicating them per bundle is harmless |
| `ratingSources`, `seerrStatus`, status vocabulary (pure data) | direct import from the owner's data module, which must be pure | data |
| `hiddenContent`, `jellyseerrAPI`, `jellyseerrUI`, `jellyseerrMoreInfo`, `requestManager`, `discoveryFilter`, `tagPipeline`, `tagCacheStore`, `tagDirectPlay`, `reinitializeTagLayout`, `reinitializeQualityTags`, `adminTags`, `bookmarks`, `spoilerBlur`, `seamlessScroll`, `downloadsPage`, `appendUserRatingToContainer` | **peer facade** `ctx.peer('hiddenContent')`, typed by the owner's `public-api.ts`, published by the owner only | stateful, cross-script |
| `JE.internals.<slot>` | **owner-only** `ctx.own.internals`. A cross-feature read (e.g. seerr reading `internals.spoilerGuard`) becomes a peer facade method | private |

Runtime property names on `window.JellyfinEnhanced` **do not change**, because built outputs, tests and the bootstrap use them. Only the typed access path changes, so this is a type-level refactor with no wire or behaviour change.

### 2.4 Enforcement (no ESLint in repo, verified: no eslint config and no eslint devDependency)
New node test `tests/frontend/architecture/feature-boundaries.test.mjs`. It is auto-discovered, because `tests/frontend/helpers/discovery.mjs:9-18` walks the folder recursively. It uses the `typescript` devDependency (6.0.3) to parse every `client/src/**/*.ts` file. It does not use regex, because comments and strings would cause false hits:
1. **Import rule:** a file in `features/<A>/` may import only `features/<A>/**`, `core/**`, `contracts/**`, `host/context.ts`, `features/shared/**`, and `features/<B>/public-api.ts`. A `features/<B>/public-api.ts` import must be `import type`, unless public-api re-exports only pure modules listed in an allowlist.
2. **host rule:** `host/**` may not import from `features/**` (after C1).
3. **internals rule:** a property access `.internals` whose object expression is a `JE`/ctx bridge is banned outside `features/<owner>/host.ts`, and so are `.internals.<slot>` reads where the slot owner ≠ the file's feature. Ownership map: `tests/frontend/architecture/internals-owners.json`. **`enhancedUi` is co-owned by settings-panel, media-tags and hidden-content** (step C4, coordinator decision D1): each one's panels create the registry on first use and fill their own members (the Media Tags and Hidden Content panels also load without the shell, in unit and browser tests), and media-tags' admin page and item editor read members back, so a single-owner facade would change behaviour; no other slot is shared beyond `features`.
4. **raw-global rule:** `window.JellyfinEnhanced` and `globalThis.JellyfinEnhanced` are allowed only in `host/context.ts`, `features/*/host.ts` (and `host-*.ts`/`*-host.ts` there), `bootstrap/**`, **the core platform hosts that stay in `host/` after C1 (`core-host.ts`, `api-host.ts`, `dom-host.ts`, `navigation-host.ts`, `session-host.ts`, `ui-host.ts`, `admin-config-host.ts`, `bootstrap-pages-host.ts`) and `core/lifecycle-entry.ts`**. Those are platform, not features: they are how the platform reaches the global, and nothing converts them, so without them strict mode (C4) cannot pass (step 1 decision; each one has a `raw-global JellyfinEnhanced` entry in the S1 baseline).
5. **Ratchet:** violations are compared with `tests/frontend/architecture/boundary-baseline.json` (`{file: count}`). New files must be at 0, and counts may only fall. Step C4 deletes the baseline, which makes the rule strict.
Run it with `node --test tests/frontend/architecture/feature-boundaries.test.mjs`.

## 3. Migration steps

Preconditions for **every** step:
- The ~650 uncommitted rewrite changes are committed first. They are not this plan's work, and the owner decides how. Work happens on a branch, or in a git worktree per parallel track.
- Never edit `component-scripts.json` or an output key in `client/entries/*.json`.
- Never hand-edit `client/generated-manifest.json`, `Jellyfin.Plugin.JellyfinEnhanced/js/**` built outputs, `docs/rewrite/migration-inventory.json` or `contracts/*.ts`. Regenerate them.

**Standard gate (G)**, run at the end of every step:
```bash
npm run client:typecheck
npm run client:build            # rewrites js/** + client/generated-manifest.json
npm run inventory:rewrite       # rewrites docs/rewrite/migration-inventory.json
npm run client:check && npm run inventory:rewrite:check
scripts/restructure-gates.sh inv    # PLAN gate INV: generate.py --check (CI: regression.yml:36) + route diff; never regenerates (review-r4 #4); js/** output paths must not change
scripts/restructure-gates.sh tool   # PLAN gate TOOL: python3 tests/run.py tooling (CI: regression.yml:134) + mutation/history path check (review-r4 #1, #2)
npm run test:client-build
node --test tests/frontend/bootstrap/bootstrap-manifest.test.mjs
npm test                        # whole tests/frontend suite (node tests/frontend/run.mjs)
git diff --exit-code restructure-base -- Jellyfin.Plugin.JellyfinEnhanced/js/component-scripts.json   # vs the base commit, not the index (review-r2 F7)
( set -e; for f in client/entries/*.json; do diff <(git show restructure-base:$f | jq -S keys) <(jq -S keys $f); done )   # output keys unchanged (review-r1 F8; the old grep was a no-op)
```
Prefer `scripts/restructure-gates.sh fe`, which wraps the above and exits non-zero on the first failure (PLAN.md step 1).
