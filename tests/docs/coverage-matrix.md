# JE regression coverage matrix

Historical issue/PR sensitivity, newly found blind spots, and remaining report-specific gaps are tracked in [history-audit.md](history-audit.md). Passing the existing suite is not completion of comprehensive coverage.

This document separates production discovery from verified behavioral coverage. A file appearing in the inventory, a test compiling, or a line being executed does **not** establish that a feature is tested. The [machine-readable inventory](production-inventory.json) enumerates every production C#, JavaScript, HTML, CSS, and JSON file outside build output, every literal HTTP route declaration, configuration/model auto-property, scheduled task, locale, and candidate storage literal. Regenerate it with `python3 tests/inventory/generate.py`; `--check` detects drift. Extraction is lexical, so computed routes/properties and inherited host behavior require review.

The project actually supports two separate artifacts: `jf10` targets .NET 9 and Jellyfin 10.11.0; `jf12` targets .NET 10 and Jellyfin 12.0.0. These are compile reference versions, not a claim that every patch release was executed. The real-host suite tests the newest release of each line instead (`jellyfin/jellyfin:10.11` and `jellyfin/jellyfin:12`, pulled on every run) and records the exact image digest and server version in each target's `report.json`. Contributor guidance naming only 10.11 is narrower than the project file.

## Status and evidence

- **Tested**: the named behavior was asserted and its suite passed in a recorded environment. It does not mean all combinations are covered.
- **Partial**: some behaviors have implemented tests; remaining cases are listed. Execution evidence must be recorded separately.
- **Unverified**: discovered and feasible, but no passing behavioral evidence has been recorded yet.
- **Blocked**: a specific unavailable prerequisite prevents the stated check.
- **Manual**: an inherently human assessment such as visual acceptability; automation can still cover neighboring behavior.

The current inventory lists 352 source/configuration/style/locale files, 173 HTTP verb/route declarations, 517 configuration and persisted-model properties, 13 scheduled tasks, and 33 locales. Counts are descriptive, not a coverage denominator. The generated inventory is authoritative if these numbers change.
